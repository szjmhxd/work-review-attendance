# Work Review 考勤判定

根据 [Work Review](https://github.com/wm94i/work-review) 的活动记录 + Edge 浏览器历史，判定某月每天「有没有工作活动」以及「非工作日是否碰了公司业务系统」。

> ⚠️ 本工具只能回答「有没有干活」，**回答不了「人当天在不在公司」**。外勤、远程办公、请假，在软件数据上可能同形；「是否到公司」必须用门禁/监控等 ground truth 核对。

## 设计原则

1. **先剔除自动化**：zTasker 定时任务（bing_search、掘金签到）会往 Edge 历史灌访问，必须先用 URL 指纹剔除，否则机器行为会被误判成人在上班。
2. **上班时段按 30 分钟槽统计覆盖**：工作日覆盖足够的槽 = 有工作活动。
3. **加班口径**：工作日超过工作时间不算加班；只有**非工作日碰公司业务系统**才算「可能加班」。
4. **软件卡退兜底**：Work Review 可能被系统卡退导致零记录（实际发生过：`0xc0000409` 崩溃 + 虚拟内存耗尽，断档 19 天），零记录 ≠ 请假，此时用 Edge 人工操作兜底。
5. **中性措辞**：结论只描述「有无工作活动 / 是否碰公司业务」，不做物理位置推断。

## 目录结构

```
.
├── attendance.py     # 主判定脚本
├── workday.py        # 工作日/休息日判断（复用自 zTasker 配置，见致谢）
├── config.json       # ★ 独立配置：工作时间、加班口径、指纹、阈值
└── README.md
```

## 快速开始

```bash
# 依赖：Python 3 + 标准库（无需第三方包）
python attendance.py 2026-07 2026-08
# 不传参数默认判断 2026-07、2026-08
```

输出一张逐日表（同时写入 `attendance.txt`），列含义：

| 列 | 含义 |
|---|---|
| WR行 / WR上班段 / idle | Work Review 记录行数、上班时段活跃时长、挂机行数 |
| 覆盖槽 | 上班时段 30 分钟槽的覆盖数（WR 活跃 ∪ Edge 人工） |
| Edge人工 | 剔除自动化后的人工浏览器访问次数 |
| URL公司 / App公司m | 命中公司 URL 的次数 / 命中公司应用标题的分钟数 |
| 结论 | 见下表 |

结论措辞（中性，不含位置推断）：

| 结论 | 含义 |
|---|---|
| 有工作活动 | 上班时段覆盖充分 |
| 有工作活动（记录偏少） | 覆盖不足但碰了公司业务 |
| 工作活动偏少 | 有少量活动 |
| ★ 几乎无活动（请假/外勤/远程皆可能） | 机器在跑、软件在跑、人几乎没操作 |
| ★ 零记录（软件卡退/未开机皆可能） | 无任何记录 |
| ★ 有公司业务操作（是否来公司待监控确认） | 休息日碰了公司系统 |
| 有活动无公司业务 | 休息日有活动但没碰公司系统 |
| 休息 | 无活动 |

## 配置（config.json）

所有判定口径都抽到 [config.json](config.json)，改配置即可调整：

- `work_hours`：上班时段（默认 08:30–12:00 / 13:00–17:30，即法定工作日的 8.30-12.00 13.00-17.30）
- `overtime_rule`：工作日超时不计加班、非工作日来才算加班
- `automation_fingerprints`：自动化任务的 URL 指纹
- `company_fingerprints`：公司业务系统指纹（URL 层 + 窗口标题层）
- `thresholds`：槽粒度、出勤门槛、公司业务停留下限等
- `data_sources`：Work Review 数据库与 Edge 历史路径

## 数据来源

- **Work Review**：`workreview.db` 的 `activities` 表（只读打开）
- **Edge 历史**：`%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\History`（`immutable=1` 只读直开，避免锁库）

## 已知局限

1. 只覆盖 Edge；Firefox/Chrome 不在统计内。
2. 自动判定只是线索，最终以人工确认/门禁监控为准。
3. Edge 历史最早只到 2026-07-16，更早的无法回溯。
4. Work Review 截图只保留 7 天、元数据保留 30 天，久远记录会滚动丢失。
